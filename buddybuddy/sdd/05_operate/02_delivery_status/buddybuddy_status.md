# 전달 상태 (05_operate / 02_delivery_status)

## 롤아웃 범위
**로컬 데모 only — 원격 배포 없음.** DEV/PROD 환경, 스테이징 게이트, 스키마 검증은
이번 작업 범위가 아니다(인메모리 단일 프로세스).

## 현재 라이브 베이스라인
- 로컬: `python -m server.web.app` → http://localhost:8010 (의존성 0, 표준 라이브러리)
- 테스트: `python -m pytest -q` → 18 passed
- 인메모리 시드: 사용자 현주·민수 온라인, 서로 버디, 시드 메시지 2건.

## 사용 방법 (두 프론트로 대화)
1. `buddybuddy/` 디렉토리에서 `python -m server.web.app` 실행.
2. 브라우저 창 **2개**를 띄운다:
   - 창 A → http://localhost:8010/?me=현주
   - 창 B → http://localhost:8010/?me=민수
3. 한 창에 메시지 입력→전송하면 1초 내 다른 창에 말풍선으로 도착(주고받는 모습).
4. 로비(http://localhost:8010/)에서 새 이름으로 접속하면 그 사용자로 로그인된다.
   버디로 추가 안 한 상대도 메시지를 보내면 대화 목록에 자동으로 뜬다.
5. http://localhost:8010/demo → 두 창을 한 페이지에서 한눈에 보기.

## 잔여 리스크 / 다음 단계(선택)
- 영속성 없음 → 재시작 시 대화 초기화. (원하면 SQLite 어댑터를 message에 주입 가능.)
- 실시간이 폴링 기반 → 웹소켓/SSE로 격상 가능(표준 라이브러리 범위 밖이라 보류).
- UI 자동 시각 게이트 미구축 → 원본 디자인이 생기면 Playwright 패리티 추가 가능.
